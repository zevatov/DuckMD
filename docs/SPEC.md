## 1. Концепция

**DuckMD** — мгновенный, красивый Markdown-ридер для macOS в стиле Apple Notes, оптимизированный под **чтение и правку отчётов и текстов от нейросетей**. Главная боль, которую решает продукт: чтобы посмотреть красиво отформатированный `.md`, сейчас нужно открыть VS Code, дождаться загрузки, нажать кнопку рендера и развернуть экран. DuckMD открывает `.md` **двойным кликом за <1 секунды** сразу в красивом виде.

**Маскот и логотип** — стильная жёлтая low-poly (гранёная) уточка в стиле Apple. Подчёркивает структуру и грани текста Markdown, теплоту и премиальный дизайн.

**Вайб продукта:** Apple Notes × Bear × Liquid Glass. Спокойная типографика, мягкие отступы, центрированная колонка чтения, жёлтый акцент (#FFC800), нативный Liquid Glass на тулбаре и поверхностях.

## 2. Целевая аудитория и сценарии

| Сценарий | Описание |
|---|---|
| **Чтение отчёта нейросети** | Пользователь получил `.md` от ChatGPT/Claude — двойной клик, мгновенно видит красивый текст. Главная ценность. |
| **Правка без знания Markdown** | Пользователь хочет поправить текст — режим «Правка» (split: код слева, живой рендер справа) + автоформатирование (Enter в списке → новый пункт, авто-закрытие `**`). |
| **Конвертация документа в MD** | Есть `.docx`/`.pdf`/`.html`/`.rtf` → перетаскивает в хаб → получает `.md`. |
| **Внешнее редактирование** | Другой агент/терминал правит тот же `.md` → DuckMD обновляет открытое окно (с таймером отмены на 5 секунд). |
| **Навигация по недавним** | Хаб показывает последние открытые файлы с превью и сортировкой. |

## 3. Функциональные требования

### 3.1. Запуск и навигация (ТРЕБУЕТСЯ)

- **R-START-1.** При запуске приложения (без указанного файла) единое окно `main` показывает **хаб-состояние** (`MainContainerView` + `showHub = true`) с недавними файлами.
- **R-START-2.** При двойном клике по `.md` в Finder — файл открывается **напрямую в режиме документа** (просмотр) в том же окне `main` (`showHub = false`, `activeDocument` установлен), минуя хаб-состояние. Без лишних рендеров, мгновенно, без мелькания хаба (холодный старт через `pendingOpenURL`/`flushPendingOpenURL` в `AppDelegate`).
- **R-START-3.** В режиме документа есть кнопка **«← Хаб»** (назад) для возврата в хаб-состояние того же окна (`showHub = true`); активный документ сохраняется в памяти (`activeDocument`).
- **R-START-4.** Хаб — НЕ отдельное окно, а состояние единого контейнера `MainContainerView` в окне `main`. Отдельного `HubWindow`/`DocumentGroup` нет. Переключение хаб↔документ — `.opacity` transition 0.18s в одном окне. Фактическая реализация — `DuckMDApp.swift` (`Window("DuckMD", id: "main")` + `MainContainerView`).

### 3.2. Хаб (ТРЕБУЕТСЯ)

- **R-HUB-1.** Сетка/список **недавних файлов** с карточками: иконка, название, мини-превью (первые строки отрендеренного текста), дата изменения.
- **R-HUB-2.** **Сортировка**: по дате открытия (по умолчанию), по дате изменения, по имени, по размеру. Переключатель в тулбаре хаба.
- **R-HUB-3.** **Поиск** по названию/содержимому недавних файлов (поле поиска вверху).
- **R-HUB-4.** **Создать новый `.md`** — кнопка «+ Новый документ» в хабе. Открывает пустой документ с запросом места сохранения.
- **R-HUB-5.** **Drag & Drop файла в хаб** → если `.md` — открывает/добавляет в недавние; если другой поддерживаемый формат (`.docx`, `.pdf`, `.html`, `.rtf`, `.txt`) → запускает конвертер в MD.
- **R-HUB-6.** Карточка файла: **одиночный клик** — открыть (как карточки действий хаба); контекстное меню — «Открыть», «Показать в Finder», «Удалить из недавних». ⚠️ Известное ограничение (v0.6.15, Этап 4): пункт «Открыть с помощью…» **не реализован** — факт в [`HubCardView.contextMenu`](../DuckMD/Views/HubCardView.swift:102), требование сохранено до реализации.
- **R-HUB-7.** Если файл из недавних **удалён с диска** — карточка показывается серой с пометкой «файл не найден», предложение убрать из списка. ⚠️ Известное ограничение (v0.6.15, Этап 4): UI серой карточки реализован ([`file.exists`](../DuckMD/Views/HubCardView.swift:31) + серый фон в [`HubCardView`](../DuckMD/Views/HubCardView.swift:84)), но **недостижим** — [`filteredAndSortedFiles`](../DuckMD/App/RecentFilesStore.swift:285) и [`load()`](../DuckMD/App/RecentFilesStore.swift:84) отбрасывают несуществующие файлы; требование сохранено до реализации.
- **R-HUB-8.** Хаб запоминает расположение и настройки сортировки между сессиями. ✅ реализовано: `sortOption` персистится в UserDefaults (`DuckMD.sortOption`).

### 3.3. Режимы документа (ТРЕБУЕТСЯ)

Документ имеет **три режима** с переключением в тулбаре (сегментированный контрол) и горячими клавишами:

| Режим | Описание | Горячая клавиша |
|---|---|---|
| **Просмотр** (`rendered`) | Красивый отрендеренный Markdown, только чтение. | `⌘1` |
| **Правка** (`split`) | Split-view: код слева + живой предпросмотр справа. Синхронно в реальном времени. | `⌘2` |
| **Код** (`code`) | Полноэкранный редактор кода с подсветкой синтаксиса Markdown. | `⌘3` |

- **R-DOC-1.** Переключение режимов плавное (`.opacity` transition, 0.18s).
- **R-DOC-2.** В режиме **Просмотр** по умолчанию при открытии файла. Только если пользователь начнёт печатать (или нажмёт «Правка») — переключается.
- **R-DOC-3.** **Split-режим**: перетаскиваемый разделитель, пропорция (`splitRatio`, по умолч. 0.5) — **диапазон 0.2–0.8** (clamp в [`SplitEditorView`](../DuckMD/Views/SplitEditorView.swift:234), запись при отпускании — [`SplitEditorView`](../DuckMD/Views/SplitEditorView.swift:238)). ⚠️ Сессия процесса: [`splitRatio`](../DuckMD/App/AppState.swift:18) — `@Published` без персиста между запусками (в отличие от R-HUB-8). Код слева влияет на рендер справа мгновенно (общий `document.text`). ✅ реализован умный центрированный скролл-синк: привязка к элементам в центре экрана (`midY`), адаптивная скорость при разной высоте блоков (код, таблицы), жёсткая доводка до верха ($y = 0$) и низа ($y = \text{maxScroll}$), защита от echo-циклов.
- **R-DOC-4.** Тулбар документа: кнопка «← Хаб», заголовок с переименованием, сегментированный переключатель режимов, меню экспорта (Копировать `⌘⇧C` / PDF / HTML / Сохранить), Markdown-шпаргалка. ✅ реализовано, включая `⌘⇧C`. ⚠️ Факт (v0.6.15, Этап 4): кнопки «Настройки» (⚙) в тулбаре документа **нет** — настройки открываются из хаба ([`SettingsLink`](../DuckMD/Views/HubView.swift:114)) и по `⌘,` (сцена `Settings` в [`DuckMDApp`](../DuckMD/DuckMDApp.swift:116)).

### 3.4. Рендер Markdown (ТРЕБУЕТСЯ)

Полная поддержка GitHub-Flavored Markdown через `swift-markdown` (cmark-gfm):

- **R-MD-1.** Заголовки H1–H6 (жёлтый акцент для H1, системный для остальных).
- **R-MD-2.** Абзацы с **жирным**, *курсивом*, ~~зачёркиванием~~, `inline-кодом`, ссылками.
- **R-MD-3.** Маркированные и нумерованные списки (вложенные).
- **R-MD-4.** Todo-чекбоксы `- [ ]` / `- [x]`. ✅ рендерятся (GFM `ListItem.checkbox`) — preview: интерактивный `input` (**не disabled**), toggle кликом через `checkboxToggleHandler` → `applyCheckboxToggle`; export — статичный span ☐/☑.
- **R-MD-5.** Цитаты `>` с жёлтой полосой.
- **R-MD-6.** Код-блоки ```` ``` ```` с указанием языка (плашка с именем языка).
- **R-MD-7.** Таблицы GFM с выравниванием колонок.
- **R-MD-8.** Горизонтальные линии `---`.
- **R-MD-9.** Изображения `![alt](url)`. ✅ Локальные: `resolveImage` + `documentURL`, рендер через `loadHTMLString(html, baseURL: docDir)` без сбоев песочницы WebKit; path traversal-защита — только пути внутри папки документа (v0.6.15, Этап 2). ✅ 404 (v0.6.15, Этап 5): локальная картинка, прошедшая резолв, но отсутствующая на диске — плейсхолдер `blocked-image` «файл изображения не найден» **без src и без пути/имени в HTML** (путь может содержать PII — [`renderImage`](../DuckMD/Parsing/MarkdownToHTML.swift:217)). ✅ HTTP — блокируются по умолчанию (плейсхолдер без URL в HTML); включаются тумблером «Загружать удалённые изображения» в Настройках (см. N-6). Limitation: путь должен быть валидным CommonMark-destination — «голый» пробел в пути без `<>`/`%20` не работает.
- **R-MD-10.** Авто-линки URL и email.
- **R-MD-11.** Умные кавычки/тире (smart punctuation, включено в swift-markdown).
- **R-MD-12.** Ограничение ширины колонки чтения (`readingWidth`, по умолч. 720pt), центрирование.
- **R-MD-13.** Поддержка тёмной/светлой темы (следует за системой, ручное переключение в настройках).

### 3.5. Редактирование и автоформатирование (ТРЕБУЕТСЯ)

- **R-EDIT-1.** Режим «Код» и «Правка» — редактор на базе `NSTextView` с подсветкой синтаксиса.
- **R-EDIT-2.** **Автоформатирование** (WYSIWYG-lite, снимает «незнание Markdown»):
  - Enter в элементе списка → новый пункт с тем же маркером.
  - Пустой пункт + Enter → выход из списка (маркер удаляется).
  - Ввод `# `/`## `/... в начале строки → заголовок.
  - Ввод `- `/`* `/`+ ` в начале → маркированный список.
  - Ввод `1. ` → нумерованный список.
  - Ввод `> ` → цитата.
  - Авто-закрытие парных символов: `**`, `*`, `` ` ``, `~~`, `_`, `()`, `[]`, `{}`. Курсор между.
  - Оборачивание выделения: выделил текст, нажал `*` → `*текст|`.
  - `Tab`/`Shift-Tab` в списке → отступ/отмена отступа.
- **R-EDIT-3.** Подсветка синтаксиса в реальном времени: заголовки, маркеры, inline-код, цитаты, ссылки.
- **R-EDIT-4.** Авто-сохранение правок в файл (debounce 1с, если файл имеет URL). ✅ hardening v0.6.15: debounce и периодическое сохранение сериализованы одной фоновой очередью; ошибки записи пробрасываются в алерт (метка сохранности честная), после записи — read-back диска; `isWriteSuspended` блокирует автосейв до явного решения пользователя.

### 3.6. Внешнее редактирование файлов (ТРЕБУЕТСЯ)

- **R-EXT-1.** Мониторинг открытого файла через **FSEvents** / `DispatchSource.makeFileSystemObjectSource`.
- **R-EXT-2.** При внешнем изменении файла → **авто-обновление** содержимого в открытом окне.
- **R-EXT-3.** Перед обновлением показывается **мягкий баннер с таймером 5 секунд** и кнопкой **«Отменить»**. При отмене — восстанавливается предыдущая версия текста (держится в памяти). ✅ hardening v0.6.15: при отмене ДО авто-применения (`previousText` пуст) отмена означает «оставить мои» — текущий текст пишется на диск с read-back, иначе диск и память остались бы в расхождении; при ошибке записи автосейв остаётся приостановлен.
- **R-EXT-4.** Если таймер истёк без действия — обновление применяется автоматически.
- **R-EXT-5.** Если у окна есть **несохранённые локальные правки** — таймер/баннер показывает «Перезаписать ваши правки? Применить / Отменить».
- **R-EXT-6.** ✅ hardening v0.6.15: внешние тексты при фокусе редактора ставятся в очередь и применяются через баннер слияния (не теряются); **удаление файла — отдельное состояние** (диалог «Восстановить / Закрыть документ», автосейв приостановлен); нечитаемый файл (в т.ч. невалидный UTF-8) — «Закрыть документ / Продолжить без записи»; невалидный UTF-8 при открытии — ошибка, документ не создаётся.

### 3.7. Конвертер в Markdown (ТРЕБУЕТСЯ)

- **R-CONV-1.** Конвертация **в Markdown** из: `.docx`, `.pdf`, `.html`, `.rtf`, `.txt`.
- **R-CONV-2.** Точка входа — **drag & drop файла в хаб** (см. R-HUB-5) или кнопка «Конвертировать» в хабе.
- **R-CONV-3.** Процесс: выбор исходного файла → выбор папки и имени для нового `.md` → конвертация → открытие результата в режиме документа. ✅ Реализация v0.6.15 (Этап 2): кнопка в хабе — NSSavePanel с выбором папки/имени; drag&drop в хаб — последовательная очередь с дефолт-папкой и автоименованием «Имя (N).md», результат сразу открывается; вход ограничен 50 МБ, PDF — 200 страницами. ✅ v0.6.15 (Этап 5): drop в окно [`ConverterView`](../DuckMD/Views/ConverterView.swift:17) тоже последовательная очередь (как хаб): подача с дедупликацией — [`enqueueConversion`](../DuckMD/Views/ConverterView.swift:276), обработка по одному — [`processNextConversion`](../DuckMD/Views/ConverterView.swift:283), окно закрывается только при пустой очереди — мультидроп больше не теряет файлы.
- **R-CONV-4.** Реализация по форматам (факт v0.6.15, Этап 4 — только системные фреймворки, [`ConverterService`](../DuckMD/Conversion/ConverterService.swift:1): Foundation/AppKit/PDFKit; `Demark`/`swift-docx` не используются — синхронно с §5):
  - `.txt` → тривиально (текст как есть, минимальная нормализация).
  - `.rtf`/`.rtfd`/`.docx`/`.html` → через `NSAttributedString(url:)` (AppKit) с маппингом bold/italic/ссылок → MD ([`ConverterService`](../DuckMD/Conversion/ConverterService.swift:80); ограничение HTML-импорта — см. N-6).
  - Факт ассоциации (v0.6.15, Этап 5): владение системы — только `.md` (`CFBundleDocumentTypes` — [`net.daringfireball.markdown`](../project.yml:58), Owner); `public.plain-text` из владения снят ([`project.yml`](../project.yml:49)) — `.txt` НЕ открывается по двойному клику, но остаётся входом конвертера и «Открыть…» ([`readableContentTypes`](../DuckMD/Models/MarkdownDocument.swift:22) содержит `.plainText`); владение ≠ способность читать (R-CONV-1/R-HUB-5).
  - `.pdf` → через `PDFKit` (`PDFDocument`), извлечение текста постранично (лимит 200 страниц); для сканов — заглушка «нужен OCR».
- **R-CONV-5.** Сохранение структуры: заголовки, списки, жирный/курсив, таблицы (где возможно).

## 7. Критерии приёмки версии 0.6.15

1. Двойной клик по `.md` → DuckMD открывается <1с, показывает красивый рендер.
2. Хаб открывается при запуске без файла, показывает недавние с превью и сортировкой.
3. Создание нового `.md` из хаба работает.
4. Конвертация из `.docx`/`.pdf`/`.html`/`.rtf`/`.txt` → `.md` работает.
5. Три режима (Просмотр/Правка/Код) переключаются, синхронны.
6. Автоформатирование работает (списки, пары, заголовки).
7. Внешнее изменение файла → авто-обновление с таймером отмены 5с; удаление/нечитаемость — явные диалоги, автосейв приостановлен до решения (hardening v0.6.15).
8. Настройки (тема, ширина, автоформат) сохраняются между сессиями.
9. Логотип-утка и версия 0.6.15 видны в About и Настройках (читаются из Bundle, единый источник — `MARKETING_VERSION` в `project.yml`); подвал хаба с версией — известное ограничение (см. R-BRAND-7).
10. Хаб и документ — состояния единого окна `main` (`MainContainerView`), отдельного окна хаба нет.
11. Дистрибуция — GitHub-flow с локальной подписью (ad-hoc / Apple Development), без Developer ID/notarization; Gatekeeper-обход документирован в `README.md`.
12. Приложение собирается чисто через `xcodegen generate && xcodebuild`.
