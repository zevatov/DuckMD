# Changelog — DuckMD

Все заметные изменения в проекте DuckMD документируются в этом файле.
Формат основан на [Keep a Changelog](https://keepachangelog.com/ru/1.0.0/), и проект придерживается [Семантического версионирования](https://semver.org/lang/ru/).

## [0.6.18] — 2026-09-27

### Улучшения
- **«Сохранить как» предлагает имя из шапки редактора:** диалог сохранения подставляет имя текущего документа из заголовка ([`suggestedSaveAsFileName()`](DuckMD/Views/ContentView.swift:774)), а не первую строку текста.
- **Хаб: ленивая сетка недавних и спокойные карточки:** сетка недавних файлов переведена на ленивую отрисовку ([`HubView`](DuckMD/Views/HubView.swift:31)); с карточки убраны бегущая строка, размытие и масштаб; даты всех карточек форматирует один общий форматтер.
- **Скролл split: превью получает долю прокрутки редактора:** пока лидер — редактор, превью прокручивается на долю его движения, без центрирования HTML-блока по строке ([`SplitEditorView`](DuckMD/Views/SplitEditorView.swift:92)); обратный путь и центральная рельса не менялись.
- **Оверлей переноса файла с текстом по экрану:** хаб и документ — «Отпустите, чтобы открыть», конвертер — «Отпустите, чтобы конвертировать» ([`FileDropOverlay`](DuckMD/Views/Components/FileDropOverlay.swift:6)); в документе оверлей скрыт, пока тянут разделитель split.
- **Хаб: устранён лаг при переносе окна:** фон хаба — непрозрачный [`Color(nsColor: .windowBackgroundColor)`](DuckMD/Views/HubView.swift:58) вместо живого размытия за окном (`VisualEffectView` c `blendingMode: .behindWindow`); тени карточек недавних сняты ([`HubCardView`](DuckMD/Views/HubCardView.swift:99)) и в покое, и при наведении — тонкая hover-обводка сохранена.

## [0.6.17] — 2026-09-26

### Критические багфиксы скролл-синхронизации (P0)
- **Устранение fight-эффекта при скролле в Split-режиме:**
  - Реализован протокол владения жестом скролла (`scrollOwner: idle/editor/preview/thumb`) вместо таймеров-догадок (0.45с/0.25с).
  - Редактор захватывает владельца при начале пользовательского скролла и освобождает строго по границам жеста: `scrollViewDidEndDragging` (без deceleration) и `scrollViewDidEndDecelerating`, плюс `NSEvent.Phase.ended` для wheel.
  - JavaScript-bridge в превью сбрасывает флаг `_isProgrammatic` только на событии `scrollend`, а не по таймеру (40/150/80мс).
  - Проверка флага `_isProgrammatic` перенесена **внутрь** `requestAnimationFrame`, предотвращая публикацию эхо-скролла во время программного движения.
  - Противоположная сторона (раб) применяет целевую позицию без публикации обратно, разрывая цикл взаимного переталкивания.

### UI/UX улучшения таблиц (P1)
- **Устранение собственного вертикального scrollbar у таблиц:**
  - `.table-container` получил `overflow: visible` вместо `overflow-x: auto`, убрав лишний scrollport.
- **Восстановление левой границы таблицы:**
  - `.table-container table` теперь `overflow: visible; border-radius: 0; border-collapse: separate; border-spacing: 0`, предотвращая clip первого бордера колонки.

## [0.6.16] — 2026-09-15

### Багфиксы и оптимизация (Root-Cause Patch)
- **Устранение ложного срабатывания алерта «Файл удалён или перемещён» при автосохранении (P0):**
  - `FileWatcherService` теперь проверяет маркер собственных записей `shouldSuppressOwnEvent?()` перед генерацией событий `.delete` / `.rename`.
  - При возникновении эхо-событий собственных атомарных перезаписей (FSEvent rename/delete при подмене файла) вотчер не показывает ложный диалог «Файл удалён», а верифицирует физическое существование файла на диске и прозрачно перепривязывает дескриптор наблюдения к новому inode (`restartWatch()`).
- **Устранение белых вспышек в режиме превью (P1):**
  - В `WebPreviewView` свойству `WKWebView` установлено `setValue(false, forKey: "drawsBackground")` для полной прозрачности веб-вью.
  - В `MainContainerView` добавлен базовый фон `Color(nsColor: .windowBackgroundColor)`, исключающий мелькание белой канвы при смене режима Split / Preview.
- **Оптимизация производительности скролла и линейки номеров строк (P1):**
  - Выделен легковесный сервис `LineIndexCache` с $O(\log K)$ бинарным поиском номеров строк и $O(1)$ смещениями вместо $O(N)$ строкового сканирования и аллокаций массива строк на каждый кадр прокрутки.
  - Устранены избыточные вызовы обновления кэша строк при скролле.
  - В `SplitEditorView` добавлен кэш диапазона активного блока и пороги отсечения дребезга скролла (`abs(delta) > 0.003`), предотвращающие циклические повторные перерисовки SwiftUI.
- **Корректный рендеринг и позиционирование широких таблиц (P2):**
  - Обновлён стиль `.table-container`: переведён на `display: block; overflow-x: auto; -webkit-overflow-scrolling: touch; padding: 14px; box-sizing: border-box;`. Широкие таблицы больше не ломают общий layout документа и не вызывают глобальный горизонтальный скролл страницы.
  - Всплывающие кнопки управления столбцами и строками таблицы позиционируются внутри безопасных отступов контейнера без срезания краев.
- **Устранение обрезки буквы в заголовке HubViewfd:**
  - В `HubView` добавлен сбалансированный отступ `.padding(.trailing, 12)` для `ToolbarItem(placement: .navigation)`, устранивший соприкосновение и обрезку буквы «D» нативной капсулой macOS Sequoia.

## [0.6.15] — 2026-09-13

### Файловый слой: защита от потери данных (релизный аудит)
- **Невалидный UTF-8 — ошибка, а не пустая строка:**
  - Открытие файла с некорректной UTF-8-кодировкой больше не подставляет пустой текст (который пустым автосейвом затёр бы оригинал): `DocumentFileService.readDocumentText` и `MarkdownDocument.init(configuration:)` кидают явную ошибку, документ не создаётся и автосохранение не стартует.
- **Ошибки записи перестали быть тихими:**
  - Все записи (автосейв, периодическое сохранение, ручное «Сохранить», экспорт HTML) пробрасывают ошибки в алерт с путём файла; метка «сохранено» обновляется только при фактическом успехе. После каждой успешной записи выполняется read-back: содержимое на диске сверяется с записанным.
- **Сериализация автосохранений:**
  - Debounce (1.0 с) и периодическое сохранение пишут через единую фоновую очередь — последний писатель определяется порядком в очереди, а не гонкой потоков.
  - Собственные записи приложения подавляются во вотчере токеном-окном (1.5 с) вместо сравнения текста с гонкой.
- **Внешние изменения без потери текста:**
  - Внешнее обновление при фокусе в редакторе больше не пропускается молча: текст ставится в очередь и предлагается через баннер слияния «Оставить мои / Применить внешние».
  - Удаление файла другим приложением — отдельный диалог «Восстановить / Закрыть документ» с приостановкой автосохранения; нечитаемый после внешнего изменения файл — диалог «Закрыть документ / Продолжить без записи».
  - Отмена внешнего изменения согласует диск и память (запись текущего текста с read-back); при ошибке записи автосохранение остаётся приостановленным.
  - Переименование из заголовка валидируется до обращения к файловой системе (запрет `/`, `\`, `..`, пустого имени) и выполняется атомарным `moveItem`.

### Превью: приватность и безопасность (релизный аудит)
- **Удалённые изображения заблокированы по умолчанию:**
  - http/https-картинки в превью больше не загружаются при открытии документа — защита от трекинг-пикселей и внешних запросов. Вместо картинки отображается плейсхолдер с alt-текстом и причиной блокировки; сам URL удалённого ресурса в HTML не попадает.
  - Управление — тумблер «Загружать удалённые изображения» в Настройках (секция «Приватность»), по умолчанию выключен. Локальные изображения документа не затрагиваются.
- **Allowlist схем ссылок:**
  - В превью кликабельны только `http://`, `https://`, `mailto:` и внутристраничные якоря `#`. Схемы `javascript:`, `file:`, `data:` и неизвестные рендерятся как обычный текст без ссылки — XSS через URI-схемы закрыт.
- **Защита локальных изображений от path traversal:**
  - `file://`-ссылки и абсолютные пути изображений работают только внутри папки самого документа: `../`, `/etc/...`, соседние директории блокируются плейсхолдером, легитимные пути рядом с документом продолжают открываться.
- **Политика навигации превью:**
  - После первичной загрузки документа любые http/https-переходы из превью уходят в системный браузер, `javascript:`/`file:`/`data:`-навигации отменяются (в логах — только схема, без путей и query).

### Производительность: большие документы и ввод (релизный аудит)
- **Парсинг больших документов ушёл в фон:**
  - Документы от 256 КБ или 4000 строк больше не блокируют открытие: первичный парсинг выполняется в фоне, на экране сразу появляется подложка темы, а контент приходит следом. Маленькие документы рендерятся синхронно, как раньше.
  - Фоновые задачи пересборки пронумерованы поколениями: устаревший результат, завершившийся позже свежего, больше не затирает готовый HTML. Смена темы больше не парсит документ повторно — пересобирается только HTML.
- **Превью плавно переживает большие правки:**
  - Замены тела превью объёмом от 200 КБ троттлятся (не чаще 175 мс) и не применяются, пока страница не догрузилась; кэш блоков скролл-синка пересобирается после каждой замены — синхронный скролл не теряет цель.
- **Подсветка редактора перестала компилировать regex на каждую строку:**
  - Все паттерны подсветки и автоформатирования списков скомпилированы один раз и переиспользуются. В документах от 2000 строк размечается видимый диапазон с запасом 200 строк вместо полной переразметки на каждый кадр.
- **Набор текста больше не тормозит хаб:**
  - Регистрация в недавних при наборе ушла с главного потока: stat, превью и подсчёт слов выполняются в фоне, а обновление карточек и запись JSON — на main. Открытие, переименование и сохранение по-прежнему регистрируются мгновенно.
- **Надёжный экспорт PDF:**
  - Экспорт получил таймаут 15 секунд: зависшая загрузка больше не удерживает webview в памяти. Каталог документа передаётся в PDF — локальные картинки больше не пропадают из экспорта молча.

### Конвертер: лимиты и предсказуемость (релизный аудит)
- **Ограничения входных файлов:**
  - До парсинга проверяются размер (лимит 50 МБ) и тип файла; пустые файлы (кроме `.txt`) и директории дают явную ошибку вместо тихого сбоя. PDF-конвертация ограничена 200 страницами — большие сканы больше не приводят к резкому росту памяти.
- **Конвертация из хаба стала предсказуемой:**
  - Кнопка «Конвертировать» открывает диалог сохранения с выбором папки и имени результата. Drop нескольких файлов ставится в последовательную очередь с защитой от дубликатов; результат именуется «Имя (2).md» при конфликте и сразу открывается в редакторе.
  - Известное ограничение: при конвертации HTML-файлов парсер может запросить внешние ресурсы самого файла (картинки) — технически не отключается, результат остаётся текстом Markdown.

### Хаб и интерфейс
- **Устранение двойной подложки логотипа DuckMD:**
  - Удалена избыточная ручная капсула в зоне навигации. Логотип `[🦆 DuckMD]` отрисовывается в единой нативной подложке macOS без вложенных контуров.
- **Шестерёнка настроек в стиле кнопок режима редактирования:**
  - Кнопка вынесена в собственный независимый `ToolbarItem(placement: .primaryAction)`. Оформлена в точности как верхние кнопки тулбара Markdown-редактора с нативной системной реакцией и отступом от поиска.
- **Адаптивная бегущая строка с градиентным затуханием в карточках:**
  - В `MarqueeText` внедрена динамическая адаптивная ширина: заголовки карточек используют всю свободную ширину до кнопки сведений `(i)`.
  - Длинные названия мягко затухают градиентом справа без троеточия `...`.
  - При наведении на карточку запускается плавный скролл «пинг-понг» с паузой в 1 секунду — точно так же, как в заголовке открытого документа.
- **Одиночная стрелочка сортировки:**
  - Из выпадающего списка сортировки удалена дублирующая ручная стрелочка, оставлен ровно один нативный системный шеврон macOS.

### Этап 5: Low hardening (релизный аудит)
- **Stale security-bookmark недавних файлов:**
  - Bookmark недавнего файла, ставший неактуальным после переноса документа (флаг stale при резолве), обновляется на лету: свежие bookmark-данные сохраняются в хранилище — следующий запуск открывает файл без деградации до fallback по сохранённому пути.
  - Контракт security-scoped доступа зафиксирован: доступ открывается строго на время синхронного чтения при открытии из хаба и освобождается сразу после; открытие документа само доступом не управляет. Без песочницы флаги — no-op, контракт держится явно.
- **Владение TXT снято (DuckMD больше не перехватывает .txt у TextEdit):**
  - Из ассоциаций приложения удалён `public.plain-text` — двойной клик по `.txt` снова открывает TextEdit; DuckMD остаётся владельцем только `.md`.
  - Открытие `.txt` через «Открыть…», drag&drop и конвертер сохранено: способность читать текстовые файлы не зависит от владения (вход конвертера R-CONV-1/R-HUB-5).
- **404 локальной картинки — плейсхолдер без утечки пути:**
  - Изображение, отсутствующее на диске внутри папки документа, больше не рендерится битым `<img>` с полным путём: вместо него плейсхолдер «файл изображения не найден» — без `src`, пути и имени файла в HTML (путь может содержать приватные данные; политика — как у заблокированных удалённых картинок).
  - Существующие локальные картинки рендерятся как раньше — контракт покрыт тестами на реальных временных файлах (кириллица, пробелы, percent-encoding).
- **Очередь дропа в окне конвертера:**
  - Перетаскивание нескольких файлов в конвертер больше не теряет файлы при активной конвертации: дроп подаётся в последовательную очередь (как в хабе), с защитой от дубликатов; окно закрывается только после обработки всех файлов, ошибка одного файла не клинит очередь.
- **Известное ограничение подтверждено (не фикс):**
  - При конвертации HTML-файлов legacy WebKit-парсер `NSAttributedString` может запросить внешние ресурсы самого файла (картинки) — публичной опции отключения нет, безопасного код-фикса без смены поведения нет. Сеть возможна только по явному действию пользователя над его собственным файлом; результат — текст Markdown.
- **Тесты:** 131 юнит-тест (TEST SUCCEEDED, 0 failures; 127 → 131: +4 новых кейса — контракт stale security-bookmark, TXT не во владении, 404-плейсхолдер без утечки пути, существующая относительная картинка рендерится).

### Этап 4: синхронизация SPEC/UX с фактом (релизный аудит, doc-only)
- **Документация приведена к реальному поведению приложения** (правки только в `.md`; код, `project.yml`, `Info.plist` и entitlements не менялись):
  - Карточка недавнего файла в хабе открывается **одиночным кликом** (как карточки действий хаба) — SPEC/UX больше не описывают двойной клик. Пункт «Открыть с помощью…» в контекстном меню не реализован и явно помечен известным ограничением (требование сохранено).
  - Серая карточка «файл не найден» помечена известным ограничением: UI есть, но хаб отфильтровывает несуществующие файлы при загрузке и в выдаче — серое состояние недостижимо.
  - Пропорция split-режима: фактический диапазон **0.2–0.8** (не 0.3–0.7); значение живёт в рамках сессии процесса и не заявлено как персистентное между запусками.
  - Кнопки «Настройки» в тулбаре документа нет — настройки открываются из хаба или по `⌘,`; ложная отметка «реализовано» снята.
  - Ширина колонки чтения — слайдер **480–1200 pt** (SPEC исправлен с 480–1000).
  - Конвертер использует **только системные фреймворки** (Foundation/AppKit/PDFKit через `NSAttributedString` + `PDFDocument`); упоминания библиотек `Demark`/`swift-docx` удалены из SPEC и UX.
